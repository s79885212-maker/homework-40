# Homework #40 — JWT авторизация

Сайт с авторизацией на JWT: страница входа, защищённая страница профиля и выход.

- Сервер: https://dummyjson.com
- Тестовый аккаунт: `emilys` / `emilyspass`

## Структура

```
homework-40/
├── login.html     — страница входа
├── profile.html   — защищённая страница профиля
├── css/style.css  — стили
├── js/auth.js     — общие функции для токенов (localStorage)
├── js/login.js    — вход, валидация, сохранение токенов
├── js/profile.js  — загрузка профиля, 401, refresh, выход
└── README.md
```

## Как проверить

1. Открыть `login.html` (лучше через Live Server).
2. Нажать «Войти» с пустыми полями — под полями появятся ошибки, запрос не уйдёт.
3. Ввести неверный пароль — «Неверный логин или пароль».
4. Ввести `emilys` / `emilyspass` — переход на `profile.html`, в Local Storage появятся `accessToken` и `refreshToken`.
5. Открыть `login.html` снова — сразу перекинет на профиль.
6. DevTools → Application → Local Storage → испортить `accessToken` и обновить страницу:
   сервер вернёт 401, сработает refresh (задача 5) и профиль загрузится с новым токеном.
   Если испортить ещё и `refreshToken` — refresh не получится и произойдёт выход на `login.html`.
7. Кнопка «Выйти» удаляет токены и возвращает на страницу входа.

## Ответы на вопросы

### 1. Из каких трёх частей состоит JWT и что хранится в каждой

JWT — это строка из трёх частей, разделённых точками: `header.payload.signature`.
Каждая часть закодирована в Base64URL.

- **Header (заголовок)** — тип токена (`JWT`) и алгоритм подписи (например, `HS256`).
- **Payload (полезная нагрузка)** — данные (claims): id пользователя, username, роль,
  время создания (`iat`) и время истечения (`exp`).
- **Signature (подпись)** — создаётся из header + payload и секретного ключа сервера.
  По ней сервер проверяет, что токен не подделан и не изменён.

### 2. Почему в JWT нельзя хранить пароль

Payload **не шифруется**, а только кодируется в Base64. Любой, у кого есть токен,
может его раскодировать (например, на jwt.io) и прочитать всё содержимое.
Токен хранится в браузере (localStorage), передаётся в каждом запросе и может утечь.
Поэтому в JWT нельзя класть пароль и другие секретные данные.

### 3. Чем access-токен отличается от refresh-токена

- **Access-токен** — короткоживущий (минуты). Отправляется в каждом запросе
  в заголовке `Authorization: Bearer <token>` и даёт доступ к защищённым данным.
- **Refresh-токен** — долгоживущий (дни). Не используется для доступа к данным,
  а нужен только для получения новой пары токенов (`POST /auth/refresh`),
  когда access-токен истёк. Так пользователю не приходится заново вводить логин и пароль.

### 4. Что означает ответ 401

`401 Unauthorized` — пользователь не авторизован: токена нет, он неверный или истёк.
Сервер не знает, кто делает запрос. В ответ на 401 клиент пробует обновить токен
через refresh, а если не получилось — удаляет токены и отправляет пользователя на вход.
